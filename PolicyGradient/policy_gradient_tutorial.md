# Policy Gradient Methods & REINFORCE: A Hands-On Tutorial with CartPole

---

## The Essential Idea (Read This First)

Q-learning and DQN both learn a **value function** — a table or network that estimates how good each (state, action) pair is. The policy is implicit: always pick the action with the highest Q-value.

**Policy gradient flips this completely:**

> Instead of learning values and deriving a policy from them, directly learn a **parameterized policy** — a neural network that maps states to action probabilities — and improve it by gradient ascent on expected reward.

The policy is now `π(a | s; θ)`: given state `s`, output a probability distribution over actions. The agent samples from this distribution to act. Training means adjusting `θ` to make good actions more probable and bad actions less probable.

**The core intuition in one sentence:**
> After each episode, look back at every action taken and ask: "Did this episode go well or badly overall?" Then nudge the policy to make those actions more likely (if well) or less likely (if badly).

**Why this is fundamentally different from DQN:**

| | DQN | REINFORCE |
|---|---|---|
| What is learned | Q(s, a) — value function | π(a\|s; θ) — policy directly |
| How it acts | argmax over Q-values | Sample from policy distribution |
| Gradient target | Bellman error (TD) | Log-probability × return |
| On/Off policy | Off-policy | On-policy |
| Memory of past | Replay buffer | No replay buffer |
| Best for | Discrete, Q-estimable tasks | Any differentiable policy |

## Part 1: Easy Concepts First

### 1.1 A Stochastic Policy Network

The policy network takes a state and outputs **action probabilities** (a probability distribution, not Q-values):

```
Input: state (4 floats for CartPole)
         ↓
   [Dense 128, ReLU]
         ↓
   [Dense 128, ReLU]
         ↓
   [Dense 2, Softmax]  ← outputs probabilities summing to 1.0
         ↓
Output: [0.73, 0.27]   ← 73% chance LEFT, 27% chance RIGHT
```

During training, the agent **samples** an action from this distribution rather than always taking the argmax. This built-in stochasticity handles exploration naturally — no epsilon-greedy needed.

During evaluation, you can either sample or take the argmax (greedy). Both are valid.

### 1.2 What Is a Return?

The **return** `G_t` at timestep `t` is the sum of all discounted future rewards from that point:

```
G_t = r_t + γ·r_{t+1} + γ²·r_{t+2} + ... + γ^{T-t}·r_T
```

For CartPole where reward = +1 every step:
- If an episode lasts 200 steps, `G_0 ≈ 200` (with γ close to 1)
- If it lasts 10 steps, `G_0 ≈ 10`

The return captures the quality of the entire trajectory from each point in time.

### 1.3 The REINFORCE Update Rule (High Level)

After one complete episode, REINFORCE updates the policy weights using:

```
For each step t in the episode:
    θ ← θ + α · G_t · ∇_θ log π(a_t | s_t; θ)
```

In plain English: if the return `G_t` was high (good episode), increase the log-probability of the action taken at step `t`. If `G_t` was low (bad episode), decrease it. The gradient `∇_θ log π` tells us which direction in weight space makes that action more probable.

### 1.4 REINFORCE Is On-Policy (No Replay Buffer)

REINFORCE must use transitions generated by the **current** policy. After each update, those old trajectories are discarded. This is the key difference from DQN:

- **DQN (off-policy):** store transitions, reuse them many times
- **REINFORCE (on-policy):** collect episode → update → discard → repeat

This makes REINFORCE **sample inefficient** (each transition used only once) but conceptually cleaner.

## Part 2: The Policy Gradient Theorem

> ⚠️ **FLAGGED — This is the hardest conceptual part. The math looks intimidating but the core insight is simple.**

### 2.1 What Are We Optimizing?

We want to maximize the **expected return**:

```
J(θ) = E_{τ~π_θ} [R(τ)]
```

where `τ` is a trajectory (sequence of states, actions, rewards) and `R(τ)` is the total return.

The challenge: we can't directly compute the gradient `∇_θ J(θ)` because the environment dynamics (how states transition) are unknown and non-differentiable. We can only observe rewards.

### 2.2 The Log-Derivative Trick

> ⚠️ **FLAGGED — This derivation is the mathematical core of all policy gradient methods.**

The key identity is:

```
∇_θ π(a|s; θ) = π(a|s; θ) · ∇_θ log π(a|s; θ)
```

This is just the chain rule: `∇ log f = (∇f) / f`, rearranged. Using this, the gradient of the objective becomes:

```
∇_θ J(θ) = E_{τ~π_θ} [ Σ_t ∇_θ log π(a_t|s_t; θ) · G_t ]
```

**Why this is magical:** The right-hand side is an expectation we can **estimate with samples** (Monte Carlo). We don't need to know the environment dynamics. We just:
1. Run one episode under the current policy
2. Compute returns `G_t` for each step
3. Compute `∇_θ log π(a_t|s_t; θ)` — this IS differentiable (it's just the gradient of the log-softmax output of our network)
4. Their product is an unbiased estimate of the true gradient

**The policy gradient theorem says:** this estimator is correct — meaning it points in the right direction on average, even though it's noisy for any single episode.

### 2.3 In Practice: Loss Function

We implement the gradient ascent update as gradient **descent** on a loss:

```
loss = − (1/T) · Σ_t [ log π(a_t | s_t; θ) · G_t ]
```

The negative sign converts ascent on J(θ) into descent (which PyTorch's optimizer does by default). The `log π(a_t | s_t; θ)` is computed by passing the state through the policy network, applying softmax, taking the log, and indexing the action taken. PyTorch's `CrossEntropyLoss` and `NLLLoss` do this automatically.

## Part 3: Variance — The Central Challenge

> ⚠️ **FLAGGED — This is the practical hardship of policy gradient methods. Understanding variance is essential for making them work.**

### 3.1 Why REINFORCE Is Noisy

The gradient estimate `G_t · ∇_θ log π(a_t|s_t; θ)` has **high variance**. Why?

Consider CartPole: one episode might last 47 steps, the next 312 steps, purely due to random initialization differences and sampling from the policy. The return `G_t` swings wildly between episodes. Large variance in `G_t` means large variance in gradient estimates, which means the optimizer takes very noisy steps — sometimes even going the wrong direction.

**Symptoms of high variance:**
- Reward curves that look like noise even after 500+ episodes
- Training that "collapses" — agent learns to balance, then forgets
- Very slow convergence compared to DQN on the same task

### 3.2 The Baseline: A Simple but Powerful Fix

> ⚠️ **FLAGGED — The baseline is the single most important practical improvement to REINFORCE.**

We can subtract any function `b(s_t)` from the return without biasing the gradient:

```
∇_θ J(θ) = E [ Σ_t ∇_θ log π(a_t|s_t; θ) · (G_t − b(s_t)) ]
```

**Why this doesn't introduce bias:** It can be shown mathematically that `E[∇_θ log π(a_t|s_t; θ) · b(s_t)] = 0` for any baseline `b` that doesn't depend on the action. So subtracting it leaves the expected gradient unchanged, but can dramatically reduce variance.

**The most common baseline:** the mean return over the episode:

```
b = mean(G_0, G_1, ..., G_T)
```

Using `(G_t − b)` instead of raw `G_t`:
- Actions taken when `G_t > b` (above-average outcome) → increase probability
- Actions taken when `G_t < b` (below-average outcome) → decrease probability

This is much more informative than just "good episode → increase everything."

**Normalized returns** (subtract mean, divide by std) is the most common implementation:

```python
returns = (returns - returns.mean()) / (returns.std() + 1e-8)
```

This keeps gradients at a consistent scale regardless of episode length, which also stabilizes the learning rate.

## Part 4: The Complete REINFORCE Algorithm

```
Initialize policy network π(a|s; θ) with random weights

For each episode:
    1. COLLECT trajectory:
       s₀ ← env.reset()
       For t = 0, 1, 2, ...:
           a_t ~ π(·|s_t; θ)         ← SAMPLE from policy
           s_{t+1}, r_t ← env.step(a_t)
           Store (s_t, a_t, r_t)
           If terminal: break
    
    2. COMPUTE returns:
       G_T = 0
       For t = T-1, T-2, ..., 0:
           G_t = r_t + γ · G_{t+1}
    
    3. NORMALIZE returns (optional but recommended):
       G̃_t = (G_t − mean(G)) / (std(G) + ε)
    
    4. COMPUTE loss:
       loss = − (1/T) · Σ_t [ log π(a_t|s_t; θ) · G̃_t ]
    
    5. BACKPROPAGATE and update θ:
       optimizer.zero_grad()
       loss.backward()
       optimizer.step()
```

Note: Steps 1-4 happen **per episode**, not per step. The entire trajectory must complete before any weight update.

## Part 5: REINFORCE with Baseline (Actor-Critic Preview)

> ⚠️ **FLAGGED — This bridges REINFORCE to Actor-Critic, which is worth understanding conceptually.**

A more principled baseline is a learned **value function** `V(s; φ)` that estimates the expected return from state `s`. This leads to the **advantage**:

```
A_t = G_t − V(s_t; φ)
```

The advantage `A_t > 0` means "this action led to better-than-expected outcomes" and `A_t < 0` means "worse than expected." Using advantage instead of raw returns dramatically reduces variance while keeping the estimator unbiased.

When you have a separate network to estimate `V(s)`, you have an **Actor-Critic** method:
- **Actor**: the policy network `π(a|s; θ)` — decides what to do
- **Critic**: the value network `V(s; φ)` — evaluates how good the state is

REINFORCE with a mean baseline is a degenerate Actor-Critic where the critic is just the episode mean — simple but effective for CartPole.

## Part 6: Comparing the Three Algorithms

| Feature | Q-Learning | DQN | REINFORCE |
|---------|-----------|-----|-----------|
| State space | Discrete | Continuous | Continuous |
| Action space | Discrete | Discrete | Discrete or Continuous |
| Policy type | Deterministic (argmax) | Deterministic (argmax) | Stochastic (sample) |
| Exploration | ε-greedy | ε-greedy | Built-in (stochastic policy) |
| Sample efficiency | High (tabular) | Medium (replay) | Low (on-policy, no reuse) |
| Variance | Low | Low | High (needs baseline) |
| Convergence | Guaranteed (tabular) | Empirical | Converges to local optimum |
| Suitable for | Maze, grid worlds | CartPole, Atari | CartPole, continuous control |

**Quiz Answers:**

Q1: **(c)** — The policy is stochastic, outputting probabilities via softmax.

Q2: **(b)** — On-policy methods require data from the current policy. After updating θ, old transitions were generated by a different policy and would give biased gradient estimates.

Q3: **(b)** — G_3 > 0 (episode gave positive reward), so the update increases log π(RIGHT | s_3), which increases π(RIGHT | s_3). A longer episode would give a larger G_3 and a stronger update.

Q4: **(b)** — Normalizing is a variance reduction technique. The gradient direction (which actions to strengthen vs. weaken) is preserved because we're just rescaling the weights on the gradient terms. Learning rate stability is a bonus: without normalization, a 500-step episode has 50× larger gradient magnitude than a 10-step episode.

Q5: (a) "Unbiased" means that the expected value of the gradient estimator equals the true gradient `∇_θ J(θ)`. On average over many episodes, the estimated gradient points in the correct direction. (b) High variance means individual estimates can point in very wrong directions. With high variance, many episodes are needed to average out the noise and make net progress. The optimizer can take steps in the wrong direction frequently, causing oscillation or collapse before converging.

Q6: The key property is that `Σ_a π(a|s; θ) · ∇_θ log π(a|s; θ) = ∇_θ Σ_a π(a|s; θ) = ∇_θ 1 = 0`. The sum of probabilities is always 1 (a constant), whose gradient is zero. So `E_a[∇_θ log π(a|s; θ) · b(s)] = b(s) · 0 = 0` for any baseline b that doesn't depend on the action. Subtracting it adds zero in expectation — no bias — but reduces variance because it centers the weights on the gradient terms.
